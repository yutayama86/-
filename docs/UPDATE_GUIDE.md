# イバトコ更新ガイド

この文書は、記事・場所情報・細かな文言・色・ナビゲーションを安全に更新するための手順書です。

## まず覚える3つの状態

コンテンツは、次の順で公開します。

1. `draft: true / reviewed: false` — 作業中。サイトには出ません。
2. `draft: true / reviewed: true` — 確認済みだが、まだ公開しません。
3. `draft: false / reviewed: true` — 公開されます。

`draft: false / reviewed: false` はエラーになります。確認していない情報を誤って公開しないための安全装置です。

## 記事を追加する

1. `src/content/articles/_template.md` をコピーします。
2. 内容に合うフォルダへ入れます。
   - `eat`：食べる
   - `life`：暮らす
   - `sauna-play`：出かける・サウナ
   - `beauty`：整える
   - `stay`：泊まる
   - `company`：働く・つくる
3. ファイル名を半角英数字とハイフンにします。例：`mito-coffee-roaster.md`
4. 取材日、現地取材の有無、担当者、出典、関係性を入力します。
5. 最後に事実・写真権利・PR表示を確認し、`reviewed: true`、公開時に `draft: false` にします。

公開前には必ず `npm run check` を実行します。

## 場所ページを追加する

丁寧な紹介ページは `src/content/places/_template.md` をコピーして作ります。多数の基本情報だけを管理する場合は `src/data/stores.csv` を使います。

場所情報では、次を公式サイト・電話・取材先確認のいずれかで照合します。

- 正式名称
- 住所、営業時間、定休日
- 価格（税・サービス料・期間条件も含む）
- 予約URL
- 写真の利用許諾
- 最終確認日 `verifiedAt`

公式窓口と確認できない予約URLは載せません。

## Editorial / Partner / PR の選び方

- `editorial`：掲載対価を受けず、編集部の判断で企画した記事
- `partner`：継続支援などの関係がある取材コンテンツ。関係性を `disclosureNote` に具体的に書く
- `pr`：制作・掲載そのものに対価がある広告。`disclosureNote` に対価・依頼関係を書く

商品提供、招待、交通費・宿泊費の負担がある場合は、区分にかかわらず `disclosureNote` に書きます。迷う場合は読者から見てより明確な `pr` を選びます。

## 細かいテキストを直す場所

| 直したいもの | ファイル |
| --- | --- |
| サイト名、説明文、連絡先、SNS | `src/data/site.ts` |
| トップページの見出し・説明 | `src/pages/index.astro` |
| ヘッダーの項目 | `src/components/SiteHeader.astro` |
| フッターの項目 | `src/components/SiteFooter.astro` |
| Aboutの文章 | `src/pages/about.astro` |
| 事業者向けページ | `src/pages/biz.astro` |
| 編集・PR・訂正方針 | `src/pages/about/` 以下 |
| カテゴリ名 | `src/data/site.ts` と `src/content.config.ts` |
| 色・文字サイズ・余白 | `src/styles/global.css` |

文言だけを直す場合は、引用符・`<`・`>`・波括弧を消さないようにします。見出し内の `<br />` は改行です。

## テキストの判断基準

### 推奨

- 「2026年8月1日に公式サイトで確認しました」
- 「編集部が現地で受け取った印象です」
- 「取材時の価格です。訪問前に公式情報をご確認ください」
- 「取材先から商品提供を受けました。記事内容は編集部が決定しています」

### 避ける

- 「絶対」「最高」「日本一」「No.1」
- 「効果がある」「必ず改善する」
- 根拠のない「人気」「評判」「プロ」「専門家」
- 実際の通常価格がない「今だけ半額」
- PRなのに「編集記事」「おすすめ」とだけ表示すること

順位、効果、比較、利用者数などを使う場合は、対象・調査主体・調査期間・母数・出典を同じ画面で確認できるようにします。

## 写真を変更する

- 実在する場所・人物の写真だけを使います。
- 撮影者と利用許諾を記録します。
- `coverAlt` は「画像」ではなく、写っている内容を短く書きます。
- 文字入り画像に重要情報を閉じ込めません。
- AI生成画像を実写の代わりに使いません。説明目的で使う場合はAI生成と明示します。

## 色や余白を変える

基本色は `src/styles/global.css` の `--color-...`、書体は `--font-brand-...` です。ページごとに新しい色を足さず、既存変数を使います。

- 本文：`--color-charcoal`
- 強い見出し：`--color-ink`
- リンク・選択状態：`--color-tide`
- 背景：`--color-paper`
- 境界線：`--color-mist` または `--color-line`

地図の44市町村の境界データは `src/data/ibaraki-geo.ts` です。形状・市町村数・地名は、出典を更新する場合を除いて変更しません。

## 公開前チェック

```bash
npm run check
```

成功後、ローカル表示を確認します。

```bash
npm run dev
```

最低限、PCとスマートフォン幅で次を確認します。

- トップ、該当記事、該当場所、エリア、問い合わせ
- 横にはみ出していない
- メニューをキーボードで操作できる
- 画像の説明が適切
- PR区分がタイトル付近に文言で表示される
- 外部リンクが正しい
- 価格・日時・予約先が取材時点から変わっていない

## 公開後の更新

- 公開確認済みの記事・場所・人物・ガイドと、コンテンツがある地域は `sitemap.xml` に自動で追加されます。空ページや未確認データは追加されません。
- 営業情報は定期的に再確認し、`verifiedAt` を更新します。
- 重要な本文修正は `updatedAt` と `corrections` に残します。
- 誤りの申し出は `src/pages/about/corrections.astro` の手順で確認・判断・履歴公開します。
- Search Consoleで「ページのインデックス」「構造化データ」「ウェブに関する主な指標」を確認します。

法令の適用は取引内容や表示全体で変わります。高額なキャンペーン、比較広告、健康・美容効果、求人、金融・医療に関する表現は、公開前に専門家へ個別確認してください。
